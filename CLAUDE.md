# LupiraCalWeb — agent notes

- **Purpose**: web UI over LupiraCalApi's REST surface (REST only, no sync-protocol paths). Visualizes the temporal backbone: calendar Class/Kind, ItemKind details, Prompt/Action payloads, completeness, availability segments, curation, tags, metadata, relations.
- **Monorepo (npm workspaces)**: root `package.json` hoists the toolchain; workspaces = `packages/domain` (`@lupira/cal-domain` — shared pure TS, consumed as source, no deps, never import generated DTO types there), `packages/tokens` (`@lupira/cal-tokens` — design tokens: light/dark `ColorScheme`, semantic palettes, spacing/typography/breakpoint; same purity rules; consumers re-type records against generated enums as the drift tripwire; new workspaces must also be added to the Dockerfile's COPY + `npm ci -w` lines), `src/LupiraCalWeb.Client`, and `apps/mobile` (Expo 57 "Lupira Calendar", package `com.lupira.calendar`, scheme `lupiracalendar`; layering `domain→data→sync→state→ui`, own orval gen against the BFF prefixes, Authentik client `lupira-cal-mobile`; program tracker in `docs/mobile/milestones.md`). Root scripts fan out (`npm run lint|typecheck|test`) or delegate (`dev|build|gen:api`).
- **Shape**: .NET 10 BFF (`src/LupiraCalWeb`) + Vite/React 19 + MUI SPA (`src/LupiraCalWeb.Client`) in one image. BFF owns Authentik OIDC (`lupira-cal` client, PKCE, no secret), cookie `__Host-lupira-cal`, Duende token refresh, YARP `/api/{**}` → cal-api root (strip `/api`, bearer attached). No anonymous surface. Dev: auto-auth + `X-Dev-User` forwarded (CalApi Development accepts it).
- **API client is generated**: orval → `src/data/api/` (gitignored from lint, `clean: true` — never hand-edit; hand-written code lives in `src/data/*.ts`). Refresh with `npm run gen:api` after CalApi endpoint changes (CalApi emits `openapi/LupiraCalApi.json` at build). Numerics generate as plain `number` (the APIs set `NumberHandling.Strict`) — never re-add `Number()` coercion at use sites.
- **UI stack (web)**: MUI v9 (Emotion; per-component default imports; v9 API only — `slots`/`slotProps`, `sx`). Theme = `ui/theme/muiTheme.ts`: `createTheme({cssVariables: {colorSchemeSelector: 'media'}, colorSchemes})` fed from tokens (teal primary), system-driven dark, breakpoint `md: 821` = the phone breakpoint (`useIsPhone` wraps `useMediaQuery`). `index.css` is bespoke-only (grids, map, contacts, drawer/modal internals) — its legacy `--bg/--text/…` vars alias `--mui-*`; never put a bespoke styling class and an MUI component on the same element (Emotion wins injection-order ties). Forms = react-hook-form (`Controller`-wrapped MUI fields; ContactEditForm gates its 8-endpoint fan-out by payload comparison, not dirtyFields). Mutation errors → `useSnackbar()` (SnackbarHost); field validation stays inline. Detail cards share `drawer/DetailDrawer.tsx`. Build splits a `vendor-mui` chunk (rolldown `advancedChunks`).
- **UI stack (mobile)**: react-native-paper 5 (MD3) themed from tokens via `ui/theme/paperTheme.ts` (+ adapted React Navigation themes); dark mode via `useColorScheme`. Confirm flows use `useConfirm()` (ConfirmDialogHost); `useUnsavedGuard` keeps `Alert.alert` (fires inside `beforeRemove`). Colors come from `useTheme()`/tokens — no hex literals except white text over calendar-colored backgrounds. Program tracker: `docs/mobile/milestones.md` (M10).
- **Layering**: `data → state → ui` (+ leaf `config/`), enforced by eslint-plugin-boundaries v7. Domain logic lives in `@lupira/cal-domain` (pure + vitest-tested: grid math, occurrence column layout, recurrence-rule/fire prose, partial dates), importable from every layer; its purity is enforced by its own eslint config.
- **Grids are hand-rolled** (no calendar lib): `GET /items?from&to` returns recurrence-expanded occurrences; grids still fan out one query per visible calendar although the occurrence DTO now carries `calendarIds` (single-query refactor pending). Proposed items ghost from `GET /calendars/{id}/proposed`; availability band joins occurrence → item detail for status.
- **Map** (`/locations`, nav label "Map"): lazy route (`React.lazy` — maplibre-gl stays in its own chunk). Data: occurrences+contacts hydrate placeIds via geo `POST /places/lookup` (`usePlaceCoords`, hand-prefixed key `/geo-api/places/lookup`); GPS via `/location-api` prefix (generated client `src/data/api-location/`, keys collision-free except `/me` — never use location's `/me` hook). Basemap = geo-api `/basemap/style.json?theme=` + pmtiles (client rewrites URLs absolute in `mapStyle.ts`; fallback wash when unprovisioned). Layer palette in `mapTokens.ts` is dataviz-validated — don't tweak hues casually; Unknown activity = dashed gray, never a fifth hue. MapLibre/React glue is centralized in `useGeoJsonLayer` (re-adds sources/layers on styledata). **maplibre-gl v6 worker gotcha**: its default worker URL (sibling of the entry module) 404s under bundlers, and bundling the worker yourself (`?worker&url`) emits an EMPTY file in prod (tree-shaken — maplibre's `sideEffects` allowlist; symptom: FF "Attempting to create a Worker from an empty source", gray map, zero `sourcedata`). Fix in place: `sync:maplibre` script vendors `maplibre-gl-worker.mjs` + `maplibre-gl-shared.mjs` verbatim into `public/maplibre/` (gitignored, runs predev/prebuild) + `setWorkerUrl('/maplibre/maplibre-gl-worker.mjs')` in `MapCanvas.tsx` — don't remove either half. A missing basemap *sprite* is equally fatal (style stuck loading); `loadMapStyle` Range-probes the pmtiles and falls back to `fallbackStyle` when assets are unprovisioned.
- **Task deadlines**: third grid source from LupiraTasksApi (`/tasks-api` BFF prefix, orval client `src/data/api-tasks/`, hook `useTaskDeadlines` — hand-prefixed query key `/tasks-api/items` to dodge cal's `/items` key + `useInvalidateItems`). Open non-Cancelled tasks with `dueAt` in range render as all-day chips (`fromTask`, `.task-deadline`/`.overdue`); click → `?task=<listId>:<itemId>` TaskCard with `lupiratasks://task/<listId>/<itemId>` deep link + tasks.lupira.com list fallback; Sidebar "Deadlines" toggle gates the fetch. Tasks-api dev listens on 8080 (Kestrel section beats ASPNETCORE_URLS).
- **/items page**: global list/search across all readable calendars in one infinite query (`useItemSearch`, skip/take paging, filters in URL params: q/tag/cal/category/status/range/from/to/parent); rows open the shared `?item=` drawer. Search covers accepted items only (never proposed). Hierarchy: one visual level — children nest under their parent's first loaded occurrence (`domain/itemTree.ts`; parent absent → flat row with `↳ parent` chip); `?parent=<id>` drills into all children (API defaults parentId searches to all-time); drawer has a HierarchyPanel (distinct from RelationsPanel's cross-API edges).
- **Known API gaps** (UI works around): no owner-list endpoint (share panel is action-only); all-day dates/kind/timezone not updatable over REST; recurrence can't be cleared (null = keep); kind details read-only except Availability.
